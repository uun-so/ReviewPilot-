# 0004. 严格证据闸门与独立校验

- 状态：已接受
- 日期：2026-11-14
- 关联：[0002](0002-verdict-taxonomy.md)、[0005](0005-single-hop-mvp.md)、[0008](0008-fail-closed-idempotency.md)

## 背景

提示词可以要求模型"只依据证据回答"，但不能证明它真的照做。模型可能把引用改写成看起来像原文的句子、用常识补全缺口，或者在证据不足时给出"支持"。产品承诺"不替模型猜"，必须由程序化闸门兜底。

## 决策

任何「支持」或「冲突」结论必须依次通过三道闸门：

1. **Schema 闸门**：模型输出经 Pydantic 校验。失败重试一次；仍失败 → 存疑。
2. **逐字引用闸门**：每条 `used_for_verdict=true` 的证据引用必须是所引文档规范化文本的**精确子串**，且文档确实在本次检索结果中。任一条不通过 → 该主张存疑。
3. **独立校验闸门**：独立 verifier 只接收主张文本、引用片段、文档标题和版本，不接收文章全文、检索过程或 judge 的推理。verifier 输出支持/反证/证据不足。只有 judge 与 verifier 的结论一致时才保留非存疑标签；不一致 → 存疑。

补充规则：

- 「支持」的全部判定证据必须来自同一篇文档（[0005](0005-single-hop-mvp.md)）。
- 判定器给出支持/冲突但没有任何可用证据 → 存疑；引用为空或全部校验失败时，不允许保留非存疑标签。
- 逐字引用失败时，允许一次带修复提示的重试（把未通过的引用回传给模型，要求逐字复制）；重试仍失败才降级存疑。重试不放松闸门。
- 判定器给出支持、但存在通过闸门的反证片段 → 程序改判为「冲突」，交由 verifier 确认。反证优先于支持，避免"有支持就不看反证"。
- verifier 不做第三次仲裁；不一致就是存疑，不引入第三个模型来"投票"。
- judge 自己的推理过程不进入 verifier 输入，避免把 judge 的错误前提传染给校验。
- 引用文本可以包含多句，但必须连续出现在源文档中。

## 备选方案

- **只靠提示词**：无法证明引用真实存在；排除。
- **只做程序化引用校验**：能防伪造引用，但不能防"引用真实、却推不出主张"；排除。
- **judge 与 verifier 不一致时取 judge**：会把校验变成装饰；排除。
- **第三次仲裁**：成本更高，且三票仍可能被同一类错误带偏；v1 不引入。

## 后果

- 假支持被压到接近零的代价是覆盖率下降；大量主张会落到「存疑」，这是预期行为。
- 闸门失败原因必须写入 `result.json` 与 trace，便于定位是检索、提示词还是模型问题。
- 校验阈值不随文章长度或 KB 大小放宽；只允许通过改进证据质量来提升覆盖率。
