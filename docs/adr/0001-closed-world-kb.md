# 0001. 闭世界知识库与证据门控

- 状态：已接受
- 日期：2026-11-14
- 关联：[0004](0004-evidence-gates.md)、[0009](0009-kb-manifest-version-conflict.md)、[0011](0011-privacy-provider-boundary.md)

## 背景

AI 生成的技术文章常见问题是"表述流畅、来源不明"：API 默认值、版本行为、性能数字看起来合理，却无法追溯到任何可检查的文本。让模型凭内部知识判断，会把"模型记得"误当成"有证据"，既不可复现，也无法审计。

ReviewPilot 的产品承诺不是"判断真假"，而是"判断在这份知识库里有没有证据，以及证据是否足够直接"。

## 决策

1. 每次核验绑定一个**版本化的本地知识库**。检索、判定、引用只允许来自这个 KB。
2. 不启联网搜索，不把模型内部知识作为兜底证据。检索不到、证据不足、版本不匹配，一律输出「存疑」。
3. 运行元数据记录 KB manifest 的 `name`、`version` 和 manifest 哈希；同一篇文章换 KB 或换版本，结论允许不同，但必须可解释。
4. 扩充覆盖范围的唯一方式是显式更新 KB 并重建索引，而不是让模型"自由发挥"。

## 备选方案

- **内置领域语料**：开箱即用，但需要持续抓取和版本维护，且覆盖永远有洞；排除。
- **实时联网检索**：覆盖广，但证据不可复现、质量参差，和"可审计"冲突；v1 排除。
- **模型内部知识兜底**：直接违背产品前提；排除。
- **混合证据分级**：长期有价值，但 v1 不引入，避免"同一结论来自不同证据等级"的语义复杂化。

## 后果

- 覆盖范围受 KB 限制；KB 未收录的真实主张也会标「存疑」。这是设计选择，不是缺陷。
- 用户需要维护 manifest、版本与来源；换来的是可复现、可审计的结论。
- 未来若引入联网或内置语料，必须作为**独立证据类别**显式标注，不能静默混入现有 KB。
