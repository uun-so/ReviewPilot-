# 0005. 单跳 MVP 与多跳延后

- 状态：已接受
- 日期：2026-11-14
- 关联：[0001](0001-closed-world-kb.md)、[0004](0004-evidence-gates.md)、[0009](0009-kb-manifest-version-conflict.md)

## 背景

技术文章里不少主张需要综合多篇文档才能判断，例如"X 在 v2 中默认关闭，因此升级后行为会变化"。多跳推理是假支持的主要来源：每一步看起来都有据，合起来却可能张冠李戴。v1 的目标是先证明"单跳也能做到零假支持"。

## 决策

1. v1 只做**单跳**：判定所依据的 `used_for_verdict=true` 证据必须来自同一篇文档，可以跨该文档的相邻块。
2. 需要跨文档才能推出的主张 → 「存疑」，原因写 `multi_hop_disabled`。
3. 「冲突」只需一份文档中的直接反证即可成立；若另有其他文档的支持线索，作为 `used_for_verdict=false` 的证据展示，并在原因中注明，不参与判定。
4. 数据模型预留 `hop_chain` 字段（v1 恒为空），未来多跳实现时不需要破坏 schema。

## 备选方案

- **允许 2 跳**：能提升覆盖率，但需要定义每一步的引用和推理链，评测成本高；v1 排除。
- **不限制跳数**：最容易产生"看似有据"的假支持；排除。
- **完全禁止冲突跨文档**：会让"文档 A 支持、文档 B 反驳"的情况无法表达；因此保留反证单跳、支持线索仅展示的规则。

## 后果

- v1 覆盖率会低于多跳方案；这是用可信度换覆盖。
- 评测集必须单独统计"因多跳被标存疑"的比例，避免把系统缺陷误读为 KB 覆盖不足。
- 多跳实现的前置条件是：每一步的引用都能独立通过闸门，且推理链可审计。
