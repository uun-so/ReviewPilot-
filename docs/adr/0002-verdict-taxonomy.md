# 0002. 三标签结论与未核验区

- 状态：已接受
- 日期：2026-11-14
- 关联：[0004](0004-evidence-gates.md)、[0009](0009-kb-manifest-version-conflict.md)、[0012](0012-output-contract.md)

## 背景

原始需求是"要么有证据支撑，要么存疑"的二元模型。但知识库可能明确反驳某条主张；把明确反证也叫「存疑」，会掩盖最危险的错误。另一方面，文章里的观点、预测、定义和修辞根本无法判定，不应污染存疑率。

## 决策

采用三个核验标签，外加一个独立的「未核验」区：

- **支持**：至少一条逐字引用能在 KB 中定位，且单独看该引用即可推出主张；所有判定证据来自同一篇文档；三道闸门通过。
- **存疑**：无法达到「支持」。包括无检索结果、无直接证据、证据不足、版本不匹配、需要跨文档综合、任一闸门失败、判定与独立校验不一致。
- **与证据冲突**：至少一条逐字反证通过闸门。冲突结论必须列出双方证据；跨版本冲突标明版本，不自动选边。conflict 要求明确否定或对同一属性给出不同具体值；省略可选参数、更简略的签名、以及“参数默认值”与“有效默认行为”的差异，不自动构成冲突。
- **未核验**：观点、预测、定义、修辞，以及锚定/抽取失败的可判定主张。展示原因，但不进入检索与判定，也不计入覆盖率分母。标题和代码块是结构内容，直接跳过句子切分，不产生核验结论。

「部分支持」不单列标签，归入「存疑」，在 `reason` 中写清哪一部分被证据覆盖。

## 备选方案

- **二元标签**：无法表达反证，且会让「冲突」与「无证据」混在一起；排除。
- **四标签以上**（部分支持、过时等）：语义更细，但标注和评测复杂度上升；v1 用原因字段承载细节。
- **把所有句子都标存疑**：会制造大量噪声，作者无法区分"需要关注"与"本来就不是主张"；排除。

## 后果

- 指标可以分开计算：假支持率、冲突召回、存疑率、覆盖率；「未核验」不进入分母。
- 报告必须分区展示，未核验内容默认可见，避免作者误以为全部通过。
- 「冲突」的语义依赖 [0009](0009-kb-manifest-version-conflict.md) 的版本策略；跨版本冲突不自动裁决。
