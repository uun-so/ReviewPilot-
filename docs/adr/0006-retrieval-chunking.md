# 0006. 检索与切块：FTS5 + jieba + 结构感知

- 状态：已接受
- 日期：2026-11-14
- 关联：[0001](0001-closed-world-kb.md)、[0005](0005-single-hop-mvp.md)、[0007](0007-deepseek-api-model-tiering.md)

## 背景

知识库是本地、版本化的，检索必须可复现，不能依赖会漂移的模型版本。中文检索有特殊问题：SQLite FTS5 的 `unicode61` 会把连续中文当成一个 token；`trigram` 对两字查询（如"超时"）实测返回空。向量检索在 v1 会引入模型版本和依赖成本，且云端 embedding 与"不整库上传"冲突。

## 决策

1. **索引**：SQLite FTS5 + jieba 预分词。中文按 jieba 分词；英文标识符、API 名、版本号、数字保留原样并做大小写归一化（仅用于检索，展示仍用原文）。
2. **切块**：结构感知，按标题层级、段落、列表、表格和代码块边界切；目标 400–600 tokens，相邻块目标 10–15% 重叠。实现上以块为单位取整，尾部重叠块不超过目标 token 的 25%，避免切断块内文本。每块保存 `doc_id`、`heading_path`、`char_start/end` 和原文。
3. **检索**：每条主张生成 1–3 条查询。规则抽取 API 名、版本号、数字、反引号内容；LLM 补充同义/上位词查询。查询侧过滤中文单字和英文停用词；多 token 查询先 AND（精度），无结果再 OR（召回）。BM25 排序，默认取 top-6，并向前后邻块扩展后再交给 judge。
4. **引用校验**：引用必须对**整篇规范化文档**做子串校验，不是对切块；切块只是检索单位。
5. **v1 不引入向量检索**。v2 可按评测结果增加本地 embedding 与混合召回；云端 embedding 仍受 [0011](0011-privacy-provider-boundary.md) 约束。
6. 代码块可以进入切块作为上下文，但不从中抽取主张（[0002](0002-verdict-taxonomy.md)）；表格中的自然语言单元格算主张。

## 备选方案

- **固定窗口切块**：实现简单，但会切断表格、代码和完整论证；排除。
- **整篇文档一块**：依赖长上下文，检索粒度太粗，成本高；排除。
- **直接上本地向量模型**：召回可能更好，但引入约 2GB 的 torch 依赖，且模型版本影响可复现性；v1 排除。
- **云端 embedding**：与闭世界/隐私边界冲突；排除。

## 后果

- 检索确定、无额外服务，但词法召回可能漏掉同义改写；评测会量化这一点。
- jieba 可能切碎英文标识符，因此必须有规则抽取和原样保留的兜底。
- 切块边界会影响召回，但不影响引用真实性；引用始终对全文校验。
