# 0003. 原子主张与逐字锚点

- 状态：已接受
- 日期：2026-11-14
- 关联：[0004](0004-evidence-gates.md)、[0012](0012-output-contract.md)

## 背景

"逐句核验"不等于"一句一结论"：一句话可能包含两个独立主张，一个主张也可能跨两句。更关键的是，LLM 直接输出的字符偏移/行号几乎必然漂移；如果报告无法精确回到原文，作者就无法确认核验对象是否被模型改写。

## 决策

1. 核验单位是**原子主张**：一句多主张拆开；相邻多句构成一个主张时，合并为一个**连续**的 `quote`；不相邻的句子若需要合并，拆成多个主张，避免伪造连续性。
2. 标题块和代码块不进入句子切分。标题是结构信息，不是主张；代码块不执行，也不从中抽取主张。正文、列表和表格中的自然语言才进入核验。
3. LLM 只返回主张的**逐字原文片段**，不返回偏移、行号或改写后的主张。
3. 程序在规范化文本中定位片段并计算 `char_start/char_end`；同一片段出现多次时，用所在段落上下文消歧。
4. 定位失败：重试一次；仍失败则丢弃该主张并写入 trace，**绝不伪造偏移**。
5. 报告按原句分组展示主张，保留 `sentence_ids` 和字符区间，支持高亮原文。
6. 锚点指向规范化文本：Markdown 原文，或 HTML 经 BeautifulSoup 抽取后的文本；原始文件保留用于审计。

## 备选方案

- **LLM 输出偏移**：实现简单，但不可靠，且失败时无法区分"模型记错"与"文章没有这句"；排除。
- **LLM 输出改写主张**：可读性好，但无法证明核验对象就是原文；排除。
- **按句子硬切**：无法表达一句多主张/多句一主张；排除。

## 后果

- 抽取阶段可能丢弃少量主张；trace 中可见丢弃原因，便于评测。
- 字符偏移让报告、评测和人工复核共享同一套锚点。
- 规范化文本的偏移不等于原始 HTML DOM 偏移；这一点必须在 README 和引用中说明。
