# 0010. 评测门槛：假支持数 = 0

- 状态：已接受
- 日期：2026-11-14
- 关联：[0002](0002-verdict-taxonomy.md)、[0004](0004-evidence-gates.md)、[0008](0008-fail-closed-idempotency.md)

## 背景

这个产品的核心价值是"支持的结论一定有据"。如果只看主观体验，很容易被流畅的报告误导；如果让模型自动标注，标注者和被测者是同类模型，无法发现系统性盲区。必须有独立的人工金标集，并且把最危险的错误——假支持——设为硬门槛。

## 决策

1. **M3 原型门槛**：2 篇 AI 技术文章、约 60 条候选主张（由句子切分生成，不含系统判定）；人工盲标（标注时看不到系统结论），使用同一 KB。假支持数必须为 0；证据逐字有效率为 100%（程序化检查）；支持一致率 ≥95%；冲突召回 ≥80%。
2. **v0.1 发布门槛**：扩到 5 篇、约 200 条主张；假支持数仍为 0；支持结论与人工一致率 ≥95%；冲突召回 ≥80%。
3. **执行机制**：`reviewpilot eval` 在全部 `human_verdict` 填完前拒绝运行；按字符区间重叠把金标与系统主张一一匹配；系统支持但金标未覆盖的主张计入 `ungraded_support`，同样使门槛失败，避免"未标注的假支持"漏网。
4. **指标定义**：
   - 假支持率 = 系统标「支持」但人工标「存疑/冲突/非主张」的条数 / 系统标「支持」的条数。门槛是**绝对条数为 0**，不是比例。
   - 支持一致率 = 双方都标「支持」的条数 / 人工标「支持」的条数。
   - 冲突召回 = 系统正确标「冲突」的条数 / 人工标「冲突」的条数。
   - 证据逐字有效率 = 通过程序化子串校验的证据条数 / 全部证据条数。
   - 覆盖率只报告，不设门槛；避免为了覆盖率牺牲假支持。
5. **标注流程**：候选主张由句子切分生成，不包含系统判定；标注者只拿主张、原文锚点和 KB，独立给出支持/存疑/冲突/非主张；分歧条目进入复核，人工结论为最终金标。
6. **数据来源**（v1）：基于公开文档快照搭建 demo KB，并生成 2 篇 AI 技术文章；后续替换为用户真实文章与 KB 时，必须重跑门槛。
7. **回归**：任何影响判定路径的改动（提示词、检索、闸门、模型）都必须重跑金标集；模型供应商静默更新后同样需要重跑。

## 备选方案

- **模型自动标注 + 人工抽查**：省时间，但存在循环论证；排除作为门槛，可作为预筛。
- **只看主观体验**：无法证明假支持率；排除。
- **以覆盖率为主要指标**：会激励系统多给结论，和产品目标相反；排除。

## 后果

- 60 条盲标大约需要 1–2 小时人工；200 条约需半天。这是发布成本的一部分。
- 门槛可能长时间阻塞发布；这是有意的：达不到零假支持就不应宣称"有据"。
- 60 条的统计置信度有限，所以 v0.1 必须扩到 200 条；报告里要注明样本量。
