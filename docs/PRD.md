# ReviewPilot 产品需求文档

版本：v0.2.2
项目：ReviewPilot — AI 技术文档事实核验 Agent
更新日期：2026-11-20

## 1. 产品概述

ReviewPilot 是面向技术内容的、知识库严格约束式事实核验工具。

#### 解决行业痛点：

- AI 生成的技术文档、教程、代码解释大量存在幻觉、参数错误、API 描述错误
- 通用大模型无法“只读指定知识库”，容易混入外部知识
- 市面工具缺少逐句原子级事实校验、证据溯源、标准化评测体系

#### 本产品核心准则：

所有判定必须来源于用户提供的知识库，无证据不妄判，有冲突必指出。

## 2. 用户群体

目标用户：个人技术作者 / 技术编辑。

- 使用场景：在自己本地机器上，针对单篇文章做发布前事实核验
- v0.1 提供 CLI；v0.2 提供本地 Web UI + HTTP API
- 当前不做：账号系统、团队多人协作、共享知识库、公网多租户

## 3. 产品能力范围（当前 v0.2.2）

- 自定义知识库构建、jieba 分词、SQLite FTS5 全文检索索引
- 文章自动分句、原子主张抽取、逐字字符锚定
- 基于知识库证据的单跳事实核验
- 三级校验机制：Schema 合规、逐字证据匹配、独立二次核验
- 版本门控：主张中的显式版本只匹配对应版本文档
- 输出结构化 `result.json`、可读 `report.md`、可复现 `trace.jsonl`
- 完整评测流水线：6 个 case / 200 条人工盲标金标
- CLI + FastAPI 后端 + React / TypeScript / Vite 前端
- 单进程作业队列、KB 白名单、localhost 默认绑定
- 结果加载竞态修复、`index.html` no-cache、页脚前端版本标识
- 支持并发控制、成本提示与失败降级

## 4. 不在本期范围（Out of Scope）

- 无账号、权限、团队协作、共享知识库
- 无公网部署与认证；默认只监听 `127.0.0.1`
- 无多跳推理、跨文档复杂推理
- 暂不支持 PDF、Word 解析
- 暂不支持向量检索 / embedding；未来按评测需要引入
- 不执行代码、不 lint、不判断代码块能否运行
- 不做批量文档审核、多作业并行（当前单 worker 串行）
- API 暂未提供 `--no-store-article` 等价开关；输入副本会保存在服务端 `runs/`

## 5. 核心功能详细需求

### 5.1 知识库管理

- 支持导入 `.md` / `.txt` / `.html` 源文件
- manifest 记录名称、版本、生效日期、敏感级别、来源、文件哈希
- 自动分词、建立本地 SQLite FTS5 索引
- CLI：`reviewpilot kb index --kb <dir>` / `kb inspect --kb <dir>`
- API：`GET /api/kbs`、`GET /api/kbs/{id}`、`POST /api/kbs/{id}/index`
- 支持查看索引状态、文档数、块数、manifest 版本
- 完全本地可复现；模型只读取检索到的 KB 片段，不整库上传

### 5.2 主张抽取

自动识别文章中所有可被证真/证伪的技术主张：

- 参数默认值
- 函数用法
- 语法规则
- 模块行为
- 版本特性描述

规则：

- 以原子主张为单位；一句多主张拆分，相邻多句可合并为连续 quote
- 模型只返回逐字原文片段，字符偏移由程序定位，失败进入「未核验」
- 自动过滤：抒情、建议、展望、主观观点
- 标题与代码块作为结构内容跳过，不进入句子切分

### 5.3 事实核验核心逻辑

每条「支持」或「冲突」结论必须经过三道校验：

1. Schema 合规校验（输出格式统一、无幻觉自由文本）
2. 证据片段逐字匹配校验（必须有原文依据，且能映射回源文档）
3. 独立二次核验（防单次模型随机错误；不一致即降级存疑）

补充规则：

- 只做单跳：判定证据必须来自同一篇文档
- 冲突要求明确否定或对同一属性给出不同具体值；未提及、机制不同、省略可选参数不构成冲突
- 版本相关主张只使用 `source_version` 匹配的片段
- 判定器给出支持但存在有效反证时，程序改判冲突
- 任何失败、空证据、校验不一致一律降级「存疑」，不允许假支持
- 模型分工：`deepseek-flash` 做抽取/检索式，`deepseek-v4-pro` 做判定/独立校验

### 5.4 输出产物

- `report.md`：可读评审报告（按原句分组，附证据与未核验原因）
- `result.json`：结构化结果（评测、二次开发、CI）
- `trace.jsonl`：完整可复现日志（检索、闸门、模型用量；不含 API Key）
- 运行元数据：文章哈希、KB manifest 哈希、模型配置、提示词版本、代码版本
- 退出码：0 无存疑无冲突 / 1 有存疑 / 2 有冲突 / 3 运行错误 / 4 未抽取到主张

### 5.5 评测系统

- 6 个 case / 200 条主张，人工盲标；标注时看不到系统结论
- 指标：
  - 假支持数（硬门槛，必须为 0）
  - 未匹配支持数（必须为 0）
  - 支持一致率
  - 冲突召回
  - 覆盖率（只报告）
  - 证据逐字有效率（必须为 100%）
- 当前结果（0.2.2）：
  - 假支持 0；未匹配支持 0
  - 支持一致率 99.1%（114/115）
  - 冲突召回 98.0%（49/50）
  - 覆盖率 100%；证据逐字有效 100%（180/180）
- M3 60 条门槛：假支持 0，支持一致率/冲突召回/证据逐字均为 100%
- 50 项 Python 测试 + 1 项前端回归测试

### 5.6 Web API 与前端

- 前端：选择 KB、读取/粘贴文章、提交核验、轮询作业、查看逐条结论与证据、下载结果
- API：
  - `GET /api/health`：版本、模型、Key 是否配置
  - `GET /api/kbs` / `GET /api/kbs/{id}`：KB 列表与状态
  - `POST /api/kbs/{id}/index`：重建索引
  - `POST /api/checks`：提交核验
  - `GET /api/jobs/{id}`：作业状态与摘要
  - `GET /api/jobs/{id}/result` / `report`：结果与报告
- 作业模型：单进程 worker 串行执行；每个作业内部并发默认 4
- 前端轮询与结果拉取分离，避免状态更新竞态；结果加载失败可重试
- `index.html` 返回 no-cache；页脚显示 `Web v0.2.2`，便于确认加载版本

### 5.7 安全与隐私

- API Key 只从服务端环境变量读取，不返回给浏览器、不写入日志
- 默认只监听 `127.0.0.1`；当前无账号体系，禁止直接暴露公网
- `internal` / `confidential` KB 必须显式确认后才发送到云端
- 文章全文与检索片段发送到 DeepSeek；KB 不整库上传
- 作业输入副本与结果保存在本地 `runs/`

## 6. 状态定义

- 支持（S）：知识库有明确原文证据匹配，且逐字引用与独立校验通过
- 冲突（C）：知识库存在明确相反、矛盾描述，或对同一属性给出不同具体值
- 存疑（U）：证据不足、信息缺失、版本不匹配、跨文档综合未启用或校验失败
- 未核验（N）：主观语句、观点、预测、定义、修辞等无法证伪内容

「部分支持」归入存疑并注明；「未核验」不计入覆盖率分母。

## 7. 非功能需求

- 可复现：记录知识库哈希、模型参数、提示词版本、代码版本
- 高可控：所有判定可溯源到文档、字符区间与逐字引用
- 安全：密钥不入日志；默认 localhost；敏感 KB 显式确认
- 稳定：失败一律降级存疑；不因单条失败中止整篇
- 成本：DeepSeek 峰谷定价；默认并发 4；目录批处理可调并发
- 可扩展：向量检索、PDF、多跳、认证、持久队列均预留扩展点
- 可部署：CLI 与 Web 共用同一判定引擎；无 Web 构建产物时 API 仍可运行

## 8. 版本迭代规划

- v0.1：完整 CLI 核验体系 + 200 条评测门槛 + wheel/sdist 发布
- v0.2（0.2.0–0.2.2）：FastAPI 后端、React / TypeScript 前端、单进程作业队列、结果加载竞态修复、no-cache 与前端版本标识
- 后续：
  - P0：v0.3 可控式混合检索 & 证据Agent多轮检索
1. 产品痛点
   当前仅单次BM25关键词检索，同义转述、语义等价的主张无法召回证据，误触发不必要 存疑；无证据充足度判断逻辑，一次检索直接下结论，面对复杂主张能力不足。
2. 迭代内容
   引入本地Embedding+向量库，实现BM25+向量混合召回
   增加轻量Agent决策层：主张拆解、证据充足度判定、自动生成新检索词、可控多轮检索
   开关控制：默认维持原有BM25稳定模式；高级模式手动开启混合检索+Agent多轮检索，全部检索过程写入trace审计日志
3. 验收门槛：新增评测集验证同义改写case，对比v0.2.2的存疑误报率；保证闭世界假设不被打破，模型不能私自使用内部知识库外知识补全证据
- P1：v0.4 跨文档多跳推理核验
1. 产品痛点
   当前规则直接对需要≥2份文档联合推导的主张标记 存疑 ；企业知识库资料分散在多份文档，大量业务场景下会产生过高误报，降低B端客户实用性。
2. 迭代内容
- 可控开关的跨文档综合能力（默认关闭）
- Agent支持关联多文档片段，校验多文档联合推导主张，审计日志标记本次核验引用的全部文档
3. 验收门槛：构建跨文档评测case，验证联合证据判定能力；保留原逻辑降级，关闭能力时行为和v0.2保持一致
- P2：
① PDF / Word解析、HTML文档抓取
 1. 产品痛点
  当前仅支持md/html/txt，企业存量文档大量是PDF、docx格式，客户使用前需要手动转格式，接入成本高；扫描类PDF存在OCR识别错误风险，破坏原文锚定定位的核心能力。
2. 迭代内容
- 支持可直接导入docx、可复制文本PDF作为知识库源文件
- 降级策略：扫描PDF提示不支持，OCR作为可选高级能力（风险提示），保留原文字符偏移锚定
 
② API认证、持久化作业队列、公网部署适配
 1. 产品痛点
当前单进程队列，服务重启任务丢失；无鉴权，无法直接公网部署交付给多用户B端客户。
2. 迭代内容
- API密钥/简单权限认证
- 持久化任务队列，重启保留任务状态
- 配置项适配公网部署（不再仅监听127.0.0.1）
 
③ 批量文档审核与CI门禁模式
 1. 产品痛点
  当前以单篇文章手动核验为主，无法嵌入企业文档自动化流程，不能作为代码/文档仓库的门禁卡点。
2. 迭代内容
- 批量提交多篇文档并行核验
- CI流水线接入模式，核验失败返回指定exit code，作为仓库合并门禁
 
④ 报告增强（中英文报告、风险分级）、KB基线快照、人工裁决闭环
 1. 产品痛点
  原有报告偏技术trace，业务人员难读懂；知识库迭代之后历史核验报告无法复现；冲突/存疑缺少人工处理入口。
2. 迭代内容
- 核验结果风险分级（高/中/低风险冲突&存疑），支持中英文导出报告
- 知识库快照基线，锁定核验时刻KB版本，保障结论可复现
- 平台内人工裁决入口，裁决结果沉淀进评测集

## 9. 当前验收标准

- 200 条金标：假支持 = 0、未匹配支持 = 0、支持一致率 ≥95%、冲突召回 ≥80%、证据逐字有效率 = 100%
- 50 项 Python 测试 + 1 项前端回归测试通过
- wheel/sdist 可构建；全新 venv 可安装并启动 CLI/API
- 前端可构建并由 FastAPI 托管；首页 no-cache；结果加载不出现无限等待
- 默认仅监听 `127.0.0.1`，不暴露公网
